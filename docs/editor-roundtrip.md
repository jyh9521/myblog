# 正文富文本 / Markdown 往返

文章正文和时间线说明共用 Sveltia CMS 0.256.1 与 R2 图片组件。工具栏「以 Markdown 编辑」切换源文与富文本，不应把图片改为普通链接，也不应改动列表结构。

## 2026-11-05 修复

旧 R2 图片正则带 `^` / `$`，只匹配整个文本节点都是图片的情况。遇到 `1. 正文。![图片](/uploads/image.png)` 或同段连续多张图片时，Lexical 的富文本导入把未识别的图片分成 `!` 文本和普通链接。原 Markdown 和右侧预览可以仍然正确，但切回富文本后的正文显示不正确。

- 图片组件改为匹配段落内的图片，而非整节点匹配；列表、正文前后缀和连续图片使用同一规则。
- `src`、`alt` 与可选 `title` 往返保留。转义描述中的 Markdown 标点、标题中的引号和反斜杠，编码文件名中的括号。
- 保留 R2 上传/选择控件、普通 HTTP(S) 图片及上传前的临时 blob 引用；保存时仍走原有 R2 流程。
- 不使用私有 Lexical 对象、切换按钮拦截或 DOM 文本替换；不禁用 Markdown 模式。
- 不批量改写已保存文章，不移动或重新上传现有图片。

## 验证

`node --test scripts/markdown-images.test.cjs` 测试实际注册的组件，不复制一套候选转换函数。涵盖段落/列表内图片、连续图片、标题与转义、编码路径、括号、外部/临时地址以及实际文章全部图片。

固定 CMS 版本的浏览器测试后端分别加载最小样例和实际文章，切换两种模式，检查编辑器内的图片组件和图片链接数量，再保存、重新打开，并以 Markdown AST 核对图片 URL/描述/标题、列表项、标题与代码块。测试页面独立于正在编辑的生产页面。

参考：[Sveltia 编辑器组件公开接口](https://sveltiacms.app/en/docs/api/editor-components)。
