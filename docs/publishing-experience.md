# 发布状态与本地草稿

## 看清保存到了哪一层

后台左下角显示原生本地草稿的数量与最近备份时间。点击它，或右下角“发布状态”，可以查看四项互不替代的结果：

1. **本地备份**：Sveltia 已写入当前浏览器 IndexedDB 的恢复副本。它不是 GitHub 提交；刚输入、尚未完成原生备份的内容不计入此处。列表逐条列出集合、条目及时间。
2. **仓库 main**：GitHub API 本次返回的最新提交 SHA。它不是某篇文章的保存回执，也不是上线证明。
3. **主站**：同源 `/hosting.json` 的 `release` 与本次查询的 main 相同，且响应头 `X-Blog-Hosting` 为 `workers-static-assets`，才显示当前 main 已回读。如果只看到 Actions 的 `Verify primary release` 步骤成功，显示流水线核验通过、实时回读待确认。
4. **Pages 回退**：只查看同一 SHA、同一运行尝试的 `deploy` job。回退失败不抹掉已核验的主站成功；旧提交、旧运行尝试的成功不冒充当前成功。

面板同时显示仓库最近提交时间与第一行说明，便于区分是哪次保存。当前编辑条目只有在主站文件清单中存在对应页面时才提供“查看已发布版本”：文章映射到 `/posts/`、游戏到 `/games/`、年表到 `/chronicles/`。新草稿与未发布路径不拼接假链接；线上链接不包含尚未保存的编辑。

发布查询在打开面板或点击“刷新发布状态”时执行，不持续轮询。每次查询先清除旧成功结果；网络失败、限流、未发现任务都显示未确认，不推断成功。正常一次查询最多读取 main、主站清单、对应 workflow、对应运行尝试的 jobs 四个端点。GitHub 为公开只读查询，不复制或发送后台登录凭据，也不修改现有登录、保存、冲突提示或发布协议。

## 导出本地草稿

1. 等待左下角的本地备份时间更新，打开面板。
2. 选择“导出本地草稿”。导出前额外等待原生 500 ms 防抖窗口结束，再读取现有备份；不会创建另一套自动保存。
3. 保留下载的 JSON 文件。它包含正文、尚未上传的 File/Blob 字节、文件名/类型/时间、Map、日期、typed array、待关联条目及恢复基准等；不是仅复制编辑框文字。

导出只读取 `github:jyh9521/myblog` 数据库的 `draft-backups` 对象仓库，不读取 `sveltia-cms.user`、cookie 或其它认证存储。未知草稿顶层字段会中止导出，不混入账号缓存。草稿正文和附件本身可能尚未公开，请自行保管备份文件。

没有草稿的情况会导出空备份；原生备份关闭、浏览器存储不可用、未触发备份的编辑、浏览器已清除的数据，均不在导出中。备份时间是读取到的原生记录时间，不是本面板另行编造的保存时间。

## 导入与恢复

1. 先处理正在编辑的内容，回到内容列表，并关闭其他后台编辑标签页。编辑页中的导入和刷新按钮保持禁用，不强制退出编辑器。首次使用的浏览器须先通过原生 CMS 初始化草稿库；扩展不创建或升级数据库结构。
2. 选择备份文件。此时只解析和预览数量，不写入任何草稿。
3. 点击“确认合并导入”。全部记录先验证完，再在**一个 IndexedDB 事务**中新增；任意同名集合/slug 冲突或写入错误会撤销整批，不覆盖、清空或删除已有备份。遇到冲突，先导出已有草稿，并在原生 CMS 中恢复处理同名条目，再重试。
4. 导入完成后不会自动刷新、提交或发布。确认当前编辑已经处理完毕后，可选择“刷新并进入原生恢复流程”，再进入原条目，接受 Sveltia 的恢复提示，核对内容后按原保存流程操作。

JSON 格式、仓库、固定 CMS 版本、配置指纹、数据类型、字段、重复键、附件字节、深度和大小均会校验。最多 1000 份草稿、64 MiB 二进制和 96 MiB 备份文件；超限会明确停止。连续换选文件、切换路由或关闭面板时，旧的校验结果不再生效。

导出附带当时 `config.yml` 的 SHA-256；导入要求当前配置相同，并原样保留每条记录的 `cmsConfigVersion`。配置指纹不是升级转换器：Sveltia 自身仍按内部配置版本决定兼容性。跨配置版本的旧草稿应在原版本后台恢复，再迁移内容；不会篡改版本让旧备份看起来兼容。浏览器导出不证明 Sveltia 已接受特定旧备份。

## 实现边界与验证

- 固定 CMS `0.256.1` 与既有构建补丁不变；扩展只通过现有独立脚本、原生草稿数据库和只读发布接口工作。
- `scripts/publishing-drafts.test.cjs` 覆盖编解码、未知字段/坏文件拒绝、配置匹配、发布判定及编辑路由保护。
- `scripts/publishing-browser.cjs` 在随机 localhost 端口、全新浏览器上下文中使用真实 IndexedDB，验证 File/Map 往返、冲突及坏文件的原子性、确认前无写入、不自动刷新、换选文件竞态、导出不含登录缓存、独立发布状态、清除旧成功、移动端布局及关闭焦点恢复。
- 浏览器脚本使用工具环境中的 Playwright，支持 `PUBLISHING_BROWSER=chromium|firefox|webkit` 与可选 `PUBLISHING_EXECUTABLE`。不把浏览器依赖加到生产包中。
- 隔离测试不编辑、保存或发布真实文章；实际线上版本与资源回读由发布验收单独记录。

```powershell
node --test scripts/publishing-drafts.test.cjs
# NODE_PATH 指向已有的 Playwright 工具环境；必要时指定已安装的浏览器执行文件。
node scripts/publishing-browser.cjs
```
