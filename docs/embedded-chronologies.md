# 游戏档案内嵌系列年表

## 使用

网站不新增年表页面、导航或独立入口，也不自动修改任何现有档案。
CMS → 游戏档案 → 选择已有档案 → **档案正文** → **插入年表**。
用直接单选按钮选择共用年表和默认查看作品，保存档案，等待部署完成。
正文使用与文章相同的编辑器，支持插图、列表、表格、PDF 和游戏卡片；位于项目信息之后、个人游玩与制作时间线之前。

Markdown 模式可在两个空行之间插入：

```text
[chronology]genesis|zephyr[/chronology]
```

`genesis` 是年表 ID，`zephyr` 是默认筛选作品 ID。省略 `|zephyr` 表示默认查看全部作品。
默认作品只是事件筛选，不代表读者已经允许该作品剧透。每个实例有独立的筛选、剧透设置和唯一锚点；不在浏览器中记住之前允许的剧透，避免下次打开意外泄底。
删除插入块即可从档案移除年表，共用数据不受影响。没有正文的旧档案保持原样。

## 整理范围

`content/chronologies/genesis.json` 首版包含 **22 个主要年代与作品节点**，不是原文逐条全译。全部标记为“资料整理”，不冒充已经核对过游戏或手册的一手证据。中文人名为索引用名，保留关键韩文原名检索词，可继续修订。
作品为创世纪战Ⅰ、Ⅱ、西风狂诗曲、暴风雨、Ⅲ Part I、Ⅲ Part II；“创世纪战外传”在此是两部外传的系列前缀，而非新增一部无具体标题的作品。
原文来源与作者在前台及每条事件内保留。原文链接含完整剧透；只记录作品开场或结尾节点时，不扩写结局。原文最后记载的年份也不被当作 Part II 结尾。
现有游戏档案里尚无这些作品，因此不为展示年表擅自创建游戏档案，不在其他作品档案里插入。

## 数据维护

CMS → **系列年表资料**。同一系列只维护一份 JSON；新建系列不需要修改组件。

- 年表 `id` 必须与文件名一致。作品、时代、来源和事件各自有稳定 ID；重命名须同步引用。
- 时代按列表顺序排列；每个时代填写纪年。事件在时代内按 `yearOrder`、`order` 排序；显示年份与排序值分开，可保留“约”“区间”“不详”。不同历法不直接比较年份，也不擅自换算公历。
- `works` 为关联作品；`spoilerWorks` 是显示该事件前必须全部允许的作品 ID。后期揭示的远古事实也要标注后期作品，不能只按发生年代标注。无剧透必须明确写 `[]`，缺失字段会使验证失败。
- 时代标题、时代说明、系列简介和来源名只放非剧透信息。
- `evidence` 区分资料整理、游戏内记载、手册记载、推断与争议；`sources` 引用来源 ID，`note` 记录不同版本、推断依据和待核实事项。未直接核对手册不能标为“手册记载”。
- `keywords` 放人物中文名、韩文原名、别名及地点。`related` 引用其他事件，只有目标也已解锁且符合当前筛选时才显示链接。
- 事件详情、注释按纯文本显示，避免数据混入 HTML；展开显示长文，主线以短摘要连续阅读。
- 年表数据是公开静态内容，剧透控制是阅读辅助，不是保密机制；原文链接单独提示剧透。
- `/chronology-catalog.json` 仅为 CMS 输出目录元数据，不含事件，也不提供独立阅读页面。

## 验证与回退

运行 `npm test && npm run check && npm run validate && npm run build`。
自动测试覆盖默认隐藏、逐作品解锁、跨作品 AND 条件、搜索不泄露、关联链接、重复实例锚点、纪年排序、CMS 单选选择与短码往返、无入口和现有档案不变。
浏览器验收在临时测试档案完成，测试档案不纳入提交与发布。
数据或引用无效会中止构建；JSON 来源链接只接受 HTTP(S)。
功能回退通过本次提交的逆向补丁或 Git revert；只撤销这次文件变更，保留后续内容编辑，遇到冲突先人工处理。
